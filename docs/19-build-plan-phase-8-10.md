ADR-013. **آزمون نفوذ را یک شرکت مستقل انجام می‌دهد، نه Claude Code.** کار Claude Code: آمادگی، اسکن خودکار، رفع، و بسته تحویل به آزمونگر.


# فاز ۱۰ — راه‌اندازی تدریجی

## ۱۰-۰ پیش‌نیاز مسدودکننده: GitLab و بازبینی کد مالی

```
تسک ۱۰-۰: فقط وقتی شروع کن که من بگویم GitLab خودمیزبان آماده است.
مخزن را به GitLab منتقل کن (تاریخچه کامل)، CI را آن‌جا راه بینداز و
محافظت شاخه را واقعاً اجباری کن (ادغام با CI قرمز ممکن نباشد).
وقتی من «گیت را انجام بده» گفتم، commitهای محلی را طبق ADR-008 push کن.
commitهای مالی فقط پس از بازبینی یک انسان ادغام شوند: فهرست فایل‌ها و
تغییرات مالی را برای بازبین آماده کن (خلاصه، ریسک، آزمون‌ها).
```

**پذیرش:** یک merge request آزمایشی با خطا در GitLab رد شود؛ هیچ کد مالی بدون تأیید بازبین ثبت‌شده ادغام نشده باشد.

## ۱۰-۱ محیط‌ها و استقرار

```
تسک ۱۰-۱: staging و production روی ابر داخلی (ارائه‌دهنده را من می‌گویم).
ایمیج‌ها از CI، استقرار از GitLab با تأیید دستی برای production، پیکربندی
از متغیر محیطی و محل امن رازها، مهاجرت‌های expand/contract بدون توقف،
پرچم‌های قابلیت به تفکیک مرکز.
همه ایمیج‌ها و بسته‌ها از mirror داخلی (ایمیج: mirror رجیستری؛ npm: یک
cache داخلی مثل Verdaccio)، تا build در دوره اینترنت ملی هم ممکن باشد.
اول فقط نقشه بده.
```

## ۱۰-۲ پایگاه داده، پشتیبان و بازیابی

```
تسک ۱۰-۲: Postgres اصلی + replica جریانی (برای گزارش)، پشتیبان پیوسته با
pgBackRest یا WAL-G روی ذخیره‌ساز S3 داخلی با رمزگذاری، بازیابی نقطه‌ای،
Redis با پایداری، ذخیره‌ساز اشیای production (ارائه‌دهنده را من می‌گویم؛
تصمیم ۲-۸). هدف RPO و RTO را از من بپرس (پیش‌فرض ۱۵ دقیقه / ۴ ساعت).
یک تمرین بازیابی کامل روی staging و ثبت زمان واقعی آن.
اول فقط نقشه بده.
```

**پذیرش:** تمرین بازیابی موفق و مستند؛ تطبیق شبانه دفتر کل روی داده بازیابی‌شده سالم.

**چک‌لیست تمرین بازیابی (ثبت ۱۴۰۵/۰۷/۲۳، دستور مالک، از تمرین مهاجرت 0085 و 0086):**

`pg_dump -Fc` یک پایگاه، آن‌چه بیرون از خود پایگاه است را **ندارد**. پس از restore این‌ها دوباره داده شوند، وگرنه migrator با `CREATE SCHEMA IF NOT EXISTS "drizzle"` خطا می‌دهد (در تمرین دیده شد؛ هیچ چیز اعمال نشد).

1. **نقش‌ها (سطح cluster):** `sepehr_owner`، `sepehr_app` و `sepehr_report`، همه `LOGIN`، نه superuser، نه `BYPASSRLS`، با رمز از مخزن راز (هرگز در فایل). راه: `pg_dumpall --roles-only` جدا، یا `pnpm db:bootstrap` که رمزها را هم از نو می‌گذارد.
2. **پایگاه:** با `-T template0`، `UTF8`، collation `en_US.utf8`. مالک همان نقش مدیر.
3. **grantهای سطح database** (همان `bootstrap.ts`). ACL درست پس از آن: `{admin=CTc, sepehr_owner=CTc, sepehr_app=c, sepehr_report=c}`.
   - `REVOKE ALL ON DATABASE <db> FROM PUBLIC`
   - `GRANT CONNECT, CREATE, TEMPORARY ON DATABASE <db> TO sepehr_owner`
   - `GRANT CONNECT ON DATABASE <db> TO sepehr_app`
   - `GRANT CONNECT ON DATABASE <db> TO sepehr_report`
4. **schema `public`** (در dump هست، ولی پس از restore بررسی شود): مالک `sepehr_owner`؛ `REVOKE ALL ON SCHEMA public FROM PUBLIC`.
5. **تنظیم‌های `ALTER DATABASE ... SET` و `ALTER ROLE ... SET`:** محلی امروز هیچ (`pg_db_role_setting` خالی). اگر در production افزوده شوند، جدا ثبت و پس از restore اعمال شوند.
6. **بررسی پس از restore:** `pg_restore --list` بی‌خطا؛ شمار `drizzle.__drizzle_migrations` برابر مبدأ؛ `drizzle-kit generate` بی تغییر؛ اتصال برنامه با `sepehr_app`؛ تطبیق شبانه دفتر کل پاک.
