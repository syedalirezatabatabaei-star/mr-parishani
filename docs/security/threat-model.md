# مدل تهدید سپهر سلامتی

> **تسک ۹-۱**، سند ۱۹ و ADR-013. تاریخ: ۱۴۰۵/۰۷/۱۸.
>
> - **خودارزیابی ASVS:** `asvs-l2-self-assessment.md`.
> - **فهرست رفع:** بخش «تسک‌های رفع» همان سند.
> - **آزمون نفوذ:** شرکت مستقل انجام می‌دهد، نه Claude Code (۹-۴ و ۹-۵).

## ۱. دارایی‌ها

| دارایی | کجا | اثر افشا یا دست‌کاری |
|---|---|---|
| **دفتر کل و کیف اعتبار** (اسناد، ثبت‌ها، مانده‌ها) | `ledger_*`، `journal_entries`، `credit_purses`، `purse_operations` | زیان مالی مستقیم، تسویه نادرست پزشک، اقساط نادرست |
| **پرداخت‌ها و تسویه** (فیش، دستور پرداخت، شبا) | `payments`، `payout_orders`، `settlement_*` | پرداخت به حساب اشتباه یا دوباره، پول‌شویی |
| **هویت اشخاص** (نام، موبایل، کد ملی، شبا، شماره چک) | `persons`، `centers`، `instruments` (کد ملی، شبا و چک رمزگذاری‌شده با blind index) | افشای داده شخصی، جعل هویت |
| **اطلاعات درمان** (پیش‌فاکتور، خدمت، نوبت، رشته) | `proformas`، `service_*`، `appointments` | افشای داده سلامت؛ محدودیت دید معوقات (سند ۰۴ §۴) |
| **اسناد بارگذاری‌شده** (مدارک اعتبار، فیش، تصویر چک، پیوست تیکت) | S3 خصوصی، لینک امضاشده کوتاه‌مدت | افشای مدارک هویتی و مالی |
| **نشست‌ها و اعتبارنامه‌ها** (کوکی، توکن، راز TOTP، گذرواژه) | `sessions`، `refresh_tokens`، `user_accounts` (درهم‌سازی و رمزگذاری‌شده) | تصاحب حساب کارکنان با دسترسی مالی |
| **رازهای سامانه** (کلید رمزگذاری فیلد، blind index، `AUTH_SECRET`، راز webhook، کاوه‌نگار، S3) | env سرور (نه مخزن، قاعده ۲۹) | شکست همه حفاظت‌های بالا |
| **سابقه ممیزی** (زنجیره درهم‌سازی) | `audit_events` | پنهان‌کاری پس از سوءاستفاده |
| **پیکربندی نسخه‌دار** (نرخ، کارمزد، سقف، دو نفره) | `config_values` | تغییر قاعده مالی بی تأیید |
| **دسترس‌پذیری** (نوبت‌دهی، پرداخت اقساط، دوره اینترنت ملی) | کل سامانه | توقف کسب‌وکار، نوبت گم‌شده |

## ۲. مرزهای اعتماد

```
[مرورگر بیمار/پزشک] --HTTPS--> [وب Next.js: CSP، nonce] --داخلی--> [API NestJS: guard، مجوز، CSRF]
[مرورگر کارکنان]    --HTTPS--> [ادمین Next.js، دامنه جدا، (محدودیت IP)] --داخلی--> [API]
[اپ موبایل (آینده)] --HTTPS، Bearer کوتاه‌عمر + refresh چرخشی--> [API]
[سرور وردپرس] --HMAC، timestamp، idempotency--> [API /leads/intake]
[API] --نقش sepehr_app (RLS، GRANT ستونی)--> [PostgreSQL] <--نقش sepehr_report (فقط‌خواندنی)-- [گزارش]
[API/worker] --> [Redis/BullMQ] --> [worker] --> [کاوه‌نگار، ClamAV، S3 داخلی، تولید PDF]
```

1. **مرورگر و وب یا ادمین:**
   - **وب:** هر ورودی نامطمئن است.
   - **صفحات سمت سرور:** کوکی را فقط به API می‌دهند.
   - **فراخوانی‌های client:** از همان origin‌اند.
2. **وب یا ادمین و API:** API به هیچ ادعای UI اعتماد نمی‌کند. مجوز، مالکیت و حوزه در لایه سرویس بررسی می‌شوند (قاعده ۱۱ تا ۱۳).
3. **وردپرس و API:** فقط امضای HMAC با زمان و کلید یکتا. وردپرس سامانه‌ای جدا با نگهداری جداست.
4. **API و پایگاه داده:** سه نقش.
   - **`sepehr_owner`:** فقط مهاجرت.
   - **`sepehr_app`:** کمینه GRANT، فقط‌افزودنی روی دفتر، RLS روی `org_nodes`.
   - **`sepehr_report`:** فقط خواندن نماهای گزارش و `analytics`.
5. **worker و سرویس‌های بیرونی داخلی** (کاوه‌نگار، S3، ClamAV): فقط خروجی، بی ورودی از کاربر به نشانی مقصد (بی SSRF).

## ۳. مهاجم‌ها

| مهاجم | توان | انگیزه |
|---|---|---|
| **M1 بیرونی ناشناس** | اینترنت، ابزار خودکار، ربات | سرنخ جعلی، شمارش موبایل، از کار انداختن، تزریق |
| **M2 بیمار یا ضامن واردشده** | حساب معتبر بیمار | دیدن پرونده دیگری (IDOR)، دست‌کاری پیش‌فاکتور یا قسط، فیش جعلی |
| **M3 پزشک، منشی یا مدیر مرکز** | حساب مرکز، دسترسی حوزه | خدمت ساختگی برای دریافت تسویه، دیدن بیمار مرکز دیگر، اعتراض سوء |
| **M4 کارمند داخلی با نقش محدود** | پنل داخلی، یک نقش (مثلاً معوقات) | عبور از نقش، دیدن اطلاعات درمان، تغییر قاعده مالی تک‌نفره |
| **M5 کارمند ارشد یا مدیر سامانه** | چند نقش، پیکربندی | دور زدن دو نفره، پاک کردن رد پا |
| **M6 دارنده نشست یا توکن ربوده‌شده** | کوکی یا refresh دزدیده | تصاحب حساب، استفاده دوباره از refresh |
| **M7 زنجیره تأمین** | بسته npm، تصویر Docker | اجرای کد در build یا زمان اجرا |
| **M8 دسترس به زیرساخت** | پشتیبان، لاگ، دیسک | خواندن داده شخصی یا راز |

## ۴. سناریوها برای هر ماژول

برای هر سناریو: کنترل موجود ← ارجاع، و در صورت نیاز تسک رفع با برچسب **R** (فهرست در خودارزیابی ASVS).

### identity

- **I1 حدس گذرواژه کارکنان (M1):**
  - argon2id با پارامترهای OWASP (`password.ts`).
  - قفل بر حساب و IP (`staff-auth.service.ts`، `identity.lockout`).
  - TOTP اجباری.
- **I2 بمباران OTP و شمارش موبایل (M1):**
  - محدودیت نرخ بر موبایل و IP (`otp-challenge.service.ts`).
  - پاسخ یکسان برای موبایل موجود و ناموجود.
- **I3 بازپخش TOTP:** `lastStep` و رد بازپخش (`totp.ts`، آزمون‌های identity).
- **I4 refresh ربوده‌شده (M6):**
  - چرخش در هر استفاده.
  - **استفاده دوباره:** کل نشست باطل می‌شود (`session.service.ts`، `refresh_token_reuse`).
- **I5 نشست وب بی‌پایان:**
  - **امروز:** مهلت بی‌کاری (`identity.session.webIdleSeconds`) هست، ولی سقف مطلق نیست.
  - **رفع:** R1.
- **I6 تغییر گذرواژه کارکنان:**
  - **امروز:** مسیر خودخدمت تغییر گذرواژه با گذرواژه فعلی نیست. فقط بازنشانی اداری هست.
  - **رفع:** R2.
- **I7 CSRF:**
  - کوکی `__Host-` با `HttpOnly`، `Secure` و `SameSite=Lax`.
  - توکن CSRF و بررسی Origin در هر درخواست تغییردهنده (`auth.guard.ts`).

### access و config

- **A1 عبور از نقش (M4):**
  - پیش‌فرض ممنوع؛ هر endpoint `@RequirePermission`.
  - بررسی در سرویس.
  - آزمون `route-access-audit`.
- **A2 IDOR (M2، M3):**
  - مالکیت و حوزه در سرویس.
  - آزمون‌های IDOR پراکنده در ماژول‌ها.
  - **رفع R3:** مجموعه کامل، یک آزمون برای هر endpoint دارای شناسه (۹-۳).
- **A3 تغییر تک‌نفره پیکربندی مالی (M5):** دو نفره با audit (`config_values`، آزمون‌های config).
- **A4 دید اطلاعات درمان برای معوقات (M4):**
  - `access.view_treatment` حذف می‌شود.
  - آزمون ۴ سند ۱۷ و آزمون‌های ۶-۷.

### lead و integrations

- **L1 سرنخ جعلی انبوه (M1):**
  - HMAC، timestamp، idempotency.
  - محدودیت بر منبع و موبایل.
  - honeypot در افزونه و سامانه (۲-۵ب، ۸-۲).
- **L2 راز webhook افشاشده:**
  - دو راز هم‌زمان برای چرخش.
  - راز فقط سمت سرور وردپرس.
  - **رفع R4:** روال چرخش در دستورالعمل.

### catalog و booking

- **C1 جست‌وجوی خودکار انبوه (M1):** محدودیت نرخ IP در جست‌وجو.
- **C2 endpointهای عمومی دیگر:** بی محدودیت نرخ برنامه.
  - **endpointها:** پروفایل، محل کار، رشته‌ها، خدمات، شهرها، تعطیلات و فهرست sitemap.
  - **رفع R5.**
- **C3 رزرو انبوه نوبت (M2):** نگه‌داشت زمان‌دار و یک‌بار برای هر بیمار (۲-۱۱).
- **C4 بارگذاری رسانه مخرب (M3):**
  - نوع واقعی (`file-type.ts`).
  - ClamAV.
  - حذف metadata و تبدیل در worker.
  - فضای خصوصی تا انتشار.

### proforma، credit، contract

- **P1 پیش‌فاکتور بالاتر از تعرفه (M3):** بازبینی انحراف (۳-۲).
- **P2 دست‌کاری امتیاز اعتباری (M4):** برگه امتیاز فقط‌افزودنی، استثنا با تأیید (۳-۵ و ۳-۶).
- **P3 مدرک جعلی (M2):** بررسی کارشناس، فایل اسکن‌شده و ذخیره خصوصی.

### ledger، wallet، service، settlement

- **F1 دست‌کاری ثبت مالی (M4، M5، M8):**
  - فقط‌افزودنی با trigger و REVOKE.
  - اصلاح فقط با سند معکوس.
  - آزمون‌های ثابت.
- **F2 دوبار پرداخت یا شارژ:** کلید idempotency و `SELECT … FOR UPDATE` (قاعده ۵).
- **F3 خدمت ساختگی (M3):** کد یک‌بارمصرف پیامک‌شده به بیمار (۴-۶) و قطعی شدن زمان‌دار.
- **F4 تسویه به شبای اشتباه (M5):**
  - شبا رمزگذاری‌شده.
  - تغییر اطلاعات مرکز با تأیید (`center_change_requests`).
  - دستور پرداخت با تأیید.
- **F5 اعتراض سوء برای نگه‌داشت (M3):** فقط قلم خود پزشک. تصمیم با حسابداری، نه بازکننده (۵-۲ و ۷-۲).

### repayment، collection، instrument

- **R-1 فیش جعلی یا تکراری (M2):** تشخیص تکرار `bank_ref_norm` و تأیید مالی (۶-۲).
- **R-2 اجرای چک بی مجوز (M4):** سه‌نفره (۶-۸).
- **R-3 دیدن تصویر چک:** لینک امضاشده کوتاه‌مدت و مجوز صریح.

### ticket، reporting، notification

- **T1 پیام داخلی به بیمار:** API آن را نمی‌دهد (آزمون ۳ سند ۱۷).
- **T2 خروجی گزارش با داده حساس:**
  - پوشاندن، مگر `reporting.export_sensitive` با دلیل.
  - ثبت هر خروجی.
  - واترمارک PDF.
- **T3 اجرای گزارش روی پایگاه عملیاتی:** اتصال جدای `sepehr_report` (آزمون ۶).
- **T4 پیامک تبلیغاتی بی رضایت:** دفتر رضایت فقط‌افزودنی. رضایت فرم وردپرس از ۸-۲.
- **T5 تزریق CSV:** خنثی‌سازی `= + - @` در خروجی‌ها (`report-files.ts` و CSV نشانی پروفایل‌ها).

### audit

- **AU1 پاک کردن رد پا (M5، M8):**
  - زنجیره درهم‌سازی و endpoint بررسی (`audit/verify`).
  - **رفع R6:** کار زمان‌بندی‌شده بررسی زنجیره، با هشدار.

### زیرساخت و زنجیره تأمین

- **S1 بسته آلوده (M7):**
  - lockfile.
  - osv-scanner، semgrep و gitleaks در CI.
  - **رفع R7:** trivy روی ایمیج‌ها در ۹-۲.
- **S2 افشای راز (M8):**
  - **امروز:** راز فقط در env و آزمون gitleaks روی کل تاریخچه هست.
  - **رفع R4:** روال چرخش کلید، از جمله بازرمزگذاری فیلدها با کلید تازه.
- **S3 پشتیبان رمزنشده (M8):** **رفع R8:** رمزگذاری پشتیبان و روال آن (۱۰-۲).
- **S4 سرآیندهای امنیتی پاسخ API:**
  - **امروز:** CSP و nosniff در وب و ادمین هست.
  - **رفع R9:**
    - nosniff و `Cache-Control: no-store` روی پاسخ‌های API.
    - HSTS در لبه TLS (۱۰-۱).
- **S5 دوره اینترنت ملی:** بی وابستگی بیرونی در زمان اجرا (قاعده ۱۷ تا ۲۰). تمرین در ۱۰-۴.
- **S6 پنل داخلی از هر شبکه:** **R10.** محدودیت IP ساخته شده (`isInternalPanelIpAllowed`)، ولی خاموش. فعال‌سازی به IP دفتر نیاز دارد (۹.۱، پرسش).
