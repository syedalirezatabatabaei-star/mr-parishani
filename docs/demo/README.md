# حالت دمو (نمایش به کارفرما)

ثبت ۱۴۰۵/۰۸/۰۷. طرح و تصمیم‌ها: [`docs/decisions/demo-mode-decisions.md`](../decisions/demo-mode-decisions.md).

دمو یک استک جداست: پروژه compose `sepehr-demo` با volumeهای خودش، روی همین ویندوز. پایگاه داده توسعه، استک staging و هیچ volume دیگری را نمی‌خواند و نمی‌نویسد. همه داده ساختگی است و از مسیر API و سرویس‌های واقعی ثبت شده است. هیچ پیامک واقعی نمی‌رود.

## فرمان‌ها (از ریشه مخزن)

| فرمان | کار | مخرب؟ |
|---|---|---|
| `pnpm demo:up` | کانتینرها، سپس API، worker، وب و پنل. Ctrl+C فقط برنامه‌ها را می‌بندد؛ داده می‌ماند. | نه |
| `pnpm demo:down` | کانتینرهای دمو را **متوقف** می‌کند (حذف نمی‌کند). | نه |
| `pnpm demo:status` | شمارش داده‌ها و توازن دفتر کل. | نه |
| `pnpm demo:seed` | پرکردن دمو، از شش ماه پیش تا امروز؛ تکرارپذیر (از مرحله ناتمام ادامه می‌دهد). در پایان snapshot می‌گیرد. | نه |
| `pnpm demo:snapshot [نام]` | پشتیبان پایگاه و فایل‌ها در `D:\sepehr_app\demo-snapshots\<نام>`. | نه |
| `pnpm demo:restore <نام>` | بازگرداندن یک snapshot. **داده فعلی دمو پاک می‌شود**؛ «DEMO» تایپ شود. | بله |
| `pnpm demo:reset` | خام کردن کامل دمو و ساخت دوباره حساب‌های کارکنان. **«DEMO» تایپ شود.** | بله |
| `pnpm demo:2fa [on\|off]` | ورود کارکنان و مراکز با رمز و TOTP (`on`، پیش‌فرض) یا فقط با رمز (`off`). بی آرگومان: وضعیت. پرچم در `ops/demo/secrets/2fa.json` است و با `demo:reset` نمی‌رود. | نه |

ترتیب معمول: `pnpm demo:reset`، سپس `pnpm demo:seed`، سپس `pnpm demo:up`. برای نمایش بعدی فقط `pnpm demo:up`، یا `pnpm demo:restore <نام>` برای برگشت به حالت پس از seed.

## نشانی‌ها

- **وب بیمار:** http://localhost:3201
- **پنل مرکز و پزشک:** http://localhost:3201/panel/login
- **پنل داخلی:** http://localhost:3202/login (فقط از همین ماشین)

## حساب‌ها

`docs/demo/demo-accounts.md` (در `.gitignore`؛ پس از seed ساخته می‌شود):
- نام کاربری، نقش و راز TOTP هر کارمند و هر حساب مرکز؛
- رمز ثابت دمو؛
- کد ورود ثابت بیماران؛
- فهرست بیماران و داستان هر کدام.

کدهای پیامکی (امضا، خدمت، رضایت) در `ops/demo/secrets/state/sms.log` چاپ می‌شوند.

## ورود فقط با رمز (`pnpm demo:2fa off`)

مالک ۱۴۰۵/۰۸/۰۹. با `off`، `pnpm demo:up` یک واسط کوچک (`apps/e2e/src/demo/totp-proxy.ts`) روی `127.0.0.1:3203` میان وب و پنل و API دمو روشن می‌کند. پس از رمز درست، واسط کد TOTP همان حساب را از راز ثبت‌شده در `seed-state.json` می‌سازد و از مسیر خود API (`/auth/totp/verify`) می‌گذراند؛ پس ممیزی، شمارش خطا و نشست همان روال همیشه است. خود API همچنان TOTP می‌خواهد (ورود مستقیم به ۳۲۰۰ `mfa_pending` می‌دهد).

- `pnpm demo:2fa on` از ورود بعدی اثر دارد، حتی وقتی دمو روشن است. `off` اگر دمو با `on` روشن شده بود، یک بار `Ctrl+C` و `pnpm demo:up` می‌خواهد.
- واسط در هیچ ایمیجی نیست (`apps/e2e`) و staging و تولید آن را ندارند.

## پس از خاموشی ناگهانی Docker

گاهی کانتینرها سالم بالا می‌آیند، ولی انتقال درگاه Docker Desktop هر اتصال را بی‌پاسخ می‌بندد
(«Connection terminated unexpectedly» یا «socket hang up»). `demo:up` و دیگر فرمان‌ها پیش از هر
کار درگاه‌های Postgres، Redis، SeaweedFS و ClamAV را می‌آزمایند و در این حالت دستور دقیق را
می‌گویند، مثلاً `docker restart sepehr-demo-postgres-1 sepehr-demo-seaweedfs-1`. ری‌استارت چیزی
حذف نمی‌کند و داده می‌ماند.

## ساعت دمو

seed روی ساعت جابه‌جاشده کار می‌کند: Postgres با libfaketime و برنامه‌ها با `ops/demo/clock-preload.mjs`، هر دو از `ops/demo/clock/faketimerc`. پس از seed ساعت `+0` (واقعی) است. **این روش فقط برای دمو است**، نه staging و نه production.

## محدودیت‌ها

- شهر «کاشان» و «شاهین‌شهر» در جدول شهرها نیستند؛ همه زیر «اصفهان» ثبت شده‌اند (یافته ۲ فایل تصمیم‌ها).
- پنل نام کاربری کارکنان را نشان می‌دهد؛ نام فارسی فقط در برگه حساب‌هاست.
- تغییر شماره بیمار seed نشده است؛ کدش از گام خود پنل به شماره تازه می‌رود.
