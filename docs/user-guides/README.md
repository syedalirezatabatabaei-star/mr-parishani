## برای همه کارکنان

1. **ورود اول:** نام کاربری و رمز موقت از مدیر سیستم، سپس رمز تازه و راه‌اندازی برنامه احراز دومرحله‌ای (TOTP، قاعده ۲۵).
   - اگر `identity.staff_mobile_required` روشن باشد، پیش از هر کار موبایل حساب با کد پیامکی تأیید می‌شود: صفحه «تأیید موبایل حساب».
2. **پنل داخلی فقط از VPN** باز می‌شود (R10).
3. **کار حساس** (تأیید دونفره، پرداخت، تغییر نرخ) کد TOTP را دوباره می‌خواهد: پنجره «تأیید هویت».
4. **تأیید دونفره:** پیشنهاد شما را همیشه نفر دیگری تأیید می‌کند (سند ۰۴ §۵). پیام «این درخواست را باید شخص دیگری جز پیشنهاددهنده تأیید کند.» یعنی همین.
5. **گوشی گم شد:** به مدیر سیستم خبر دهید. بازنشانی TOTP دونفره است و همه نشست‌های شما بسته می‌شوند.
6. **هیچ داده بیمار** (نام، کد ملی، موبایل، شرح درمان) در پیام‌رسان، ایمیل یا تیکت عمومی نوشته نشود؛ فقط شماره پرونده.

## شکاف‌های پیداشده هنگام نوشتن این راهنماها (۱۴۰۵/۰۷/۲۳)

> **به‌روز ۱۴۰۵/۰۷/۲۴:** هر سه بسته شد: صفحه مشاور `/leads` (`bca8a61`)، صفحه نقش‌ها `/access` (`1069c46`)، و صفحه تنظیمات `/settings` برای کلیدهای هویت، سرنخ، نوبت و پیامک (`26b02a3`). `wallet.credit_transfer_enabled` هنوز صفحه ندارد. متن پایین سابقه است.

1. **مشاور صفحه‌ای در هیچ پنلی ندارد.**
   - API سرنخ، پرونده، تخصیص و نوبت برای بیمار ساخته شده است: `leads`، `lead`، `booking`، مجوزهای `lead.*` و `booking.book_for_patient`.
   - ولی هیچ صفحه‌ای در پنل داخلی یا پنل مراکز آن را صدا نمی‌زند. **مانع راه‌اندازی است.**
2. **مدیریت نقش‌ها و دسترسی‌ها صفحه ندارد.** ساخت نقش و دادن نقش امروز فقط با فرمان `pnpm access:grant` یا مستقیم با API (`/api/v1/access`) ممکن است.
3. **پیکربندی:** چند کلید صفحه دارند:
   - «پرونده‌های اعتباری» ← قواعد: `credit.plans`، `credit.scoring_ruleset`، دلایل رد، کمیته، کسری کم و قالب قرارداد؛
   - «نرخ‌های تسویه پزشک»؛
   - «تعطیلات».

   **بقیه کلیدها صفحه ندارند.** از جمله سه پرچم هویت (`identity.*`) که روز راه‌اندازی باید روشن شوند، `wallet.credit_transfer_enabled`، و کلیدهای سرنخ، نوبت و پیامک. پیشنهاد و تأیید دونفره آن‌ها امروز فقط با API (`/api/v1/config`) است.

هر سه در RESUME، «موانع راه‌اندازی»، برای تصمیم مالک ثبت شده‌اند.
