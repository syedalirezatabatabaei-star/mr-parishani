# ۰۷ — برنامه ساخت فاز ۰ و ۱

دستورها را **یکی‌یکی** به Claude Code بدهید. پیش از هر تسک `/plan` بگیرید، نقشه را بخوانید، بعد اجازه اجرا بدهید. تا وقتی معیار پذیرش یک تسک سبز نشده، سراغ تسک بعد نروید.

> پیش از شروع: مخزن GitLab خودمیزبان آماده باشد، Node.js LTS و pnpm نصب باشد، و Docker برای Postgres و Redis محلی در دسترس باشد.

---

## فاز ۰ — پایه

### ۰-۱ اسکلت مخزن

```
یک monorepo با pnpm workspaces و Turborepo بساز طبق ساختار بخش ۵ فایل CLAUDE.md.
apps/api (NestJS)، apps/worker، apps/web (Next.js)، apps/admin (Next.js)،
packages/contracts، packages/ui، packages/config.
TypeScript در حالت strict برای همه بسته‌ها. ESLint و Prettier با قواعد مشترک.
یک قانون lint اضافه کن که import مستقیم بین ماژول‌های apps/api/src/modules را ممنوع کند.
docker-compose برای Postgres 17 و Redis در محیط توسعه.
```

**پذیرش:** `pnpm build` و `pnpm lint` و `pnpm test` بدون خطا اجرا می‌شوند؛ تلاش برای import بین دو ماژول، خطای lint می‌دهد.

### ۰-۲ خط CI

```
خط CI در GitLab بساز که این مراحل را اجرا کند:
type check، lint، آزمون واحد، آزمون یکپارچه با Testcontainers،
اسکن اسرار با gitleaks، اسکن وابستگی با osv-scanner، تحلیل ایستا با semgrep،
و یک مرحله build که ایمیج Docker بسازد.
ادغام در main بدون سبز شدن همه مراحل ممکن نباشد.
```

**پذیرش:** یک merge request آزمایشی با یک خطای تایپی، در CI رد می‌شود.

### ۰-۳ زیرساخت پایگاه داده

```
Drizzle را راه‌اندازی کن با مهاجرت‌های دستی و بررسی‌شده.
قواعد پایه: شناسه UUIDv7، ستون‌های created_at و updated_at و deleted_at،
مبالغ همیشه bigint با پسوند _rial، زمان‌ها timestamptz.
یک کاربر پایگاه داده با حداقل دسترسی برای برنامه بساز.
یک ابزار کمکی برای تبدیل و نمایش تاریخ شمسی و یکسان‌سازی متن فارسی
(ی/ك و ارقام) در packages/contracts بنویس، با آزمون کامل.
```

**پذیرش:** آزمون‌های تبدیل تاریخ شمسی شامل سال کبیسه و اسفند ۲۹ روزه سبز است.

### ۰-۴ هویت و نشست

```
ماژول identity را بساز طبق docs/04-roles-and-access.md:
ورود بیمار با OTP (محدودیت نرخ بر شماره و IP و دستگاه، قفل موقت)،
ورود کارکنان و مراکز با رمز argon2id به‌علاوه TOTP اجباری،
کوکی HttpOnly + Secure + SameSite با محافظت CSRF برای وب،
توکن کوتاه‌عمر و refresh چرخشی با تشخیص استفاده مجدد برای موبایل،
مدیریت دستگاه‌های فعال و خروج از همه دستگاه‌ها.
سرویس پیامک را پشت رابط SmsProvider با پیاده‌سازی کاوه‌نگار و یک پیاده‌سازی
ساختگی برای آزمون بنویس. ارسال از صف با تلاش مجدد و timeout.
```

**پذیرش:** آزمون‌ها نشان می‌دهند ۶ تلاش ناموفق OTP قفل موقت می‌سازد؛ refresh استفاده‌شده دوباره پذیرفته نمی‌شود.

### ۰-۵ دسترسی و سابقه

```
ماژول access را بساز: مجوزها به‌صورت ثابت در packages/contracts،
نقش‌ها و ترکیبشان در پایگاه داده، حوزه دسترسی (شهر، مرکز، پزشک، صف، پرونده خودم).
درخت مراکز با parent_id و path، به‌همراه Row-Level Security.
قید سخت: منشی هرگز بیشتر از دسترسی پزشکش دسترسی ندارد.
یک نگهبان (guard) بساز که هر endpoint بدون اعلام مجوز صریح را در زمان راه‌اندازی رد کند.
فیلتر سطح فیلد در لایه سریال‌سازی خروجی.
ماژول audit: جدول فقط افزودنی با زنجیره هش و پارتیشن ماهانه.
```

**پذیرش:** هر شش آزمون بخش ۸ سند `04-roles-and-access.md` سبز است؛ endpoint بدون مجوز باعث خطای راه‌اندازی برنامه می‌شود.

### ۰-۶ پیکربندی نسخه‌دار

```
ماژول config را بساز: جدول‌های پیکربندی نسخه‌دار با تاریخ اعتبار و
سلسله‌مراتب سراسری ← شهر ← فیلد درمان ← مرکز یا پزشک.
تابع resolve(key, scope, at) که مقدار مؤثر را برمی‌گرداند.
تغییر پیکربندی حساس نیازمند تأیید دونفره و ثبت در سابقه.
هیچ مصرف‌کننده‌ای نباید مقدار را مستقیم از جدول بخواند.
```

**پذیرش:** آزمون نشان می‌دهد تغییر نرخ امروز، مقدار مؤثر یک رکورد قدیمی را عوض نمی‌کند.

### ۰-۷ رویداد و صف

```
جدول outbox و worker پردازش آن را با BullMQ بساز.
هر رویداد در همان تراکنش نوشته می‌شود؛ پردازش idempotent است.
پایش: OpenTelemetry، سلامت صف، و هشدار روی رشد صف.
```

**پذیرش:** آزمون با قطع شبیه‌سازی‌شده نشان می‌دهد هیچ رویدادی گم یا دوبار اجرا نمی‌شود.

## فاز ۱ — دفتر کل و کیف اعتبار

سند مرجع: `docs/02-ledger-and-wallet.md` — پیش از هر تسک کامل خوانده شود.

### ۱-۱ اسکلت دفتر کل

```
ماژول ledger را بساز: جدول‌های ledger_account و journal_entry و ledger_entry
طبق بخش ۲ سند ۰۲. پارتیشن ماهانه روی ledger_entry.
در مهاجرت، مجوز UPDATE و DELETE روی این جدول‌ها از کاربر برنامه REVOKE شود.
تنها راه نوشتن، سرویس postJournal است که سند نامتوازن را رد می‌کند.
idempotency_key اجباری. entity_id روی هر سند.
```

**پذیرش:** تلاش برای `UPDATE` مستقیم روی `ledger_entry` از سمت برنامه خطا می‌دهد؛ سند نامتوازن رد می‌شود.

### ۱-۲ کیف اعتبار

```
ماژول wallet را بساز با حساب‌های منطقی بخش ۳ سند ۰۲.
عملیات: تصویب اعتبار، شارژ، رزرو، لغو رزرو، ثبت مصرف، قطعی شدن،
ابطال مانده، سند معکوس.
هر عملیات داخل تراکنش با SELECT ... FOR UPDATE روی ردیف کیف.
قیدهای غیرقابل عبور بخش ۴ در کد، نه در پیکربندی.
در همه متن‌های رابط کاربری «کیف اعتبار»، هرگز «کیف پول».
```

**پذیرش:** آزمون‌های ۱ تا ۳ و ۶ و ۸ بخش ۸ سند ۰۲ سبز است؛ ۵۰ درخواست هم‌زمان برداشت، مانده منفی نمی‌سازد.

### ۱-۳ اقساط

```
سرویس تولید برنامه اقساط:
مبنای سررسید تاریخ واریز؛ قاعده روز ۳۱ و ۳۰ و اسفند ۲۹ روزه طبق بخش ۵ سند ۰۲؛
گردکردن رو به پایین با واحد پیکربندی و افزودن تمام ته‌مانده به قسط اول.
بدون جریمه دیرکرد و بدون تخفیف تسویه زودهنگام.
تخصیص پرداخت: قدیمی‌ترین قسط سررسیدشده؛ مازاد در suspense.unallocated.
```

**پذیرش:** آزمون ویژگی‌محور با ۱۰٬۰۰۰ ترکیب تصادفی نشان می‌دهد جمع اقساط همیشه برابر کل تعهد است؛ سررسیدها در همه طول‌های ماه درست‌اند.

### ۱-۴ تطبیق و گزارش سلامت مالی

```
کار شبانه تطبیق: مقایسه مانده محاسباتی با نمای مادی‌شده،
گزارش تراز بدهکار و بستانکار هر شرکت، و هشدار فوری روی هر مغایرت.
replica فقط‌خواندنی برای گزارش پیکربندی شود.
```

**پذیرش:** ایجاد مغایرت مصنوعی در محیط آزمایشی، هشدار تولید می‌کند.

## قواعد ثابت حین کار

1. هر تسک روی شاخه جدا، با پیام commit روشن و به‌روزرسانی `CHANGELOG.md`.
2. هیچ تسکی بدون آزمون ادغام نمی‌شود.
3. هر جا تصمیم کارفرما لازم است، `TODO(decision)` نوشته شود و **حدس زده نشود**.
4. پس از هر فاز، یک برچسب نسخه زده شود تا برگشت ممکن باشد.
5. کد مالی و دسترسی، حتی با آزمون سبز، پیش از استقرار عملیاتی توسط یک بازبین انسانی خوانده شود.

- رفع ایرادهای ۱ تا ۶ فایل اکسل امتیازدهی (سند ۰۳ بخش ۷)
- نحوه پیگیری پزشک دارای مانده بدهکار پس از قطع همکاری
- قواعد نظام پزشکی برای محتوای پروفایل عمومی پزشکان
- مدت نگهداری مدارک و فایل‌های بارگذاری‌شده
