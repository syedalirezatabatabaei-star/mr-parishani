# درگاه: درخواست همکاری، حساب مرکز، محتوای پیشخوان و اعلان‌ها (دستور مالک ۱۴۰۵/۰۸/۱۰)

## تصمیم‌های تأییدشده مالک
- migration فقط افزودنی (جدول و مجوز تازه)؛ فقط روی پایگاه دمو/محلی. اعمال روی پایگاه اصلی منتظر «تأیید شد».
- ضدربات خودمیزبان بی‌تصویر: محدودیت نرخ (موبایل و IP)، سقف پیامک روزانه، proof-of-work سبک، honeypot. هیچ سرویس خارجی.
- حساب مرکز: پیامک «نام کاربری + پیوند یک‌بارمصرف ۲۴ ساعته»؛ توکن فقط هش‌شده؛ رمز را خود کاربر می‌گذارد و TOTP در اولین ورود (همان جریان موجود) فعال می‌شود؛ محدودیت تلاش.
- تأیید درخواست همکاری دونفره: کارشناس شبکه درمان «تأیید اولیه» (مرکز با همان مسیر موجود در وضعیت پیش‌نویس ساخته می‌شود)، مدیر شبکه درمان «تأیید نهایی» (حساب + نقش مدیر مرکز فقط روی همان مرکز + پیامک پیوند). فعال‌سازی مرکز همان جریان دونفرهٔ قبلی؛ هیچ فعال‌سازی خودکار.
- محتوا (بنر، صفحه متنی، اطلاعیه): پیشنهاد مدیر سیستم، تأیید پشتیبانی یا مدیر سیستم دیگر (نفر دوم ≠ پیشنهاددهنده)، نسخه‌بندی و audit.
- ورود بیمار: فقط ظاهر؛ مراحل «موبایل ← کد ← آماده». بدون فرم پروفایل تازه.

## خلاصهٔ SQL مهاجرت 0110 (فقط افزودنی)
- `partnership_requests`: درخواست (شماره پیگیری ترتیبی برای نمایش، نام مرکز، نوع، شخص، شهر، رشته‌ها، نشانی، تلفن، پروانه، مسئول، موبایل تأییدشده، پزشکان jsonb، وضعیت `pending|reviewed|approved|rejected`، دلیل رد، بررسی‌کننده/تأییدکننده، مرکز و حساب ساخته‌شده، IP هش‌شده). CHECKها برای وضعیت و دونفره (approved_by ≠ reviewed_by).
- `partnership_request_documents`: مدرک (نوع، کلید فایل خصوصی، نوع محتوا، اندازه، sha256).
- `partnership_request_events`: تاریخچه (فقط افزودنی، trigger رد UPDATE/DELETE).
- `account_setup_tokens`: توکن یک‌بارمصرف (هش، حساب، انقضا، استفاده، تلاش‌ها).
- `dashboard_banners`: نسخه‌های بنر (کلید بنر، نسخه، عنوان، متن، رنگ، لینک و متن دکمه، ترتیب، شروع/پایان، مخاطبان، فعال، مدت نمایش، وضعیت proposed/approved/rejected، پیشنهاد/تصمیم).
- `content_pages`: نسخه‌های صفحه متنی (slug، نسخه، عنوان، بدنهٔ ساخت‌یافته jsonb، وضعیت، پیشنهاد/تصمیم).
- `announcements`: نسخه‌های اطلاعیه (کلید، نسخه، عنوان، متن، مخاطب، فوری، شروع/پایان، فعال، وضعیت).
- `inbox_notifications`: اعلان سیستمی هر حساب (نوع، عنوان، متن، لینک، کلید یکتایی، خوانده‌شدن).
- `announcement_reads`: خوانده‌شدن اطلاعیه برای هر حساب.
- مجوزهای تازه: `config.propose_content` (مدیر سیستم)، `config.approve_content` (پشتیبانی، مدیر سیستم)، `catalog.review_partnership` (کارشناس شبکه درمان)، `catalog.approve_partnership` (مدیر شبکه درمان). هیچ مجوز موجود عوض یا برداشته نمی‌شود.
- قالب‌های پیامک تازه: `partnership.received`، `partnership.rejected`، `partnership.account_ready` (مخاطب staff).
- دسترسی جدول‌ها به نقش برنامه (`sepehr_app`) مثل جدول‌های دیگر؛ events و قالب‌ها بدون UPDATE.
