# حضور و سقف جاری در صفحه تخصیص (۱۴۰۵/۰۷/۲۴، دور نوزدهم)

پیشنهاد دور هفدهم بند ۹: «خواندن حضور و سقف جاری». غیرمالی، بی مهاجرت، بی مجوز تازه.

## تصمیم‌ها

1. **فقط افزودنی در پاسخ موجود:** `GET /lead/assignment/shares` برای هر سهم دو فیلد تازه دارد: `presence` و `maxOpenCases`. endpoint تازه ساخته نشد.
2. **همان قاعده موتور:** آخرین ردیف `agent_presence` و `agent_caps` (`created_at DESC, id DESC`)، همان که `AssignmentService.eligible` می‌خواند. بی ردیف: `present` و بی‌سقف.
3. **صفحه:** ستون «حضور و سقف جاری»؛ فرم‌های حضور و سقف با مقدار جاری شروع می‌شوند و پس از ثبت، صفحه دوباره خوانده می‌شود (`router.refresh`).
4. **مجوز:** همان `lead.manage_assignment` مسیر سهم‌ها.

## آزمون‌ها

- `test/lead/assignment-page.int.test.ts`: **تغییر کرد (سخت‌تر، نه ضعیف‌تر).** شکل دقیق سهم دو فیلد تازه را دارد؛ و پس از تغییر حضور و سقف، مقدار جاری (آخرین) خوانده می‌شود.
- جهش «قدیمی‌ترین حضور به‌جای آخرین»: قرمز.
