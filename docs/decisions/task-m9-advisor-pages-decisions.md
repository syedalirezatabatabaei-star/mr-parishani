# صفحه‌های مشاور (م۹) — تصمیم‌ها

دستور مالک ۱۴۰۵/۰۷/۲۴ (بند ۵): «هر کار غیرمالی و بدون ورودی مالک که مانده انجام بده (صفحه‌های پنل مشاور …)». غیرمالی؛ بی مهاجرت؛ بی تغییر رفتار API.

## ساخته شد (پنل داخلی)

- **`/leads`، «سرنخ‌ها و پرونده‌ها»** (`lead.read_cases`، `lead.intake_manual`):
  - پرونده‌های باز (پیش‌فرض) یا همه، به دامنه بیننده: مشاور فقط پرونده‌های خودش (`own`).
  - ثبت سرنخ دستی از همان یک ورودی (سند ۰۵ §۱): موبایل، نام، کد ملی، رشته، شهر، یادداشت، رضایت پیامک. نتیجه («سرنخ تازه»، «تکراری»، «بازگشتی»…) و پیوند پرونده.
- **`/leads/[id]`:** شخص (موبایل‌های تأییدشده، چهار رقم کد ملی، مسدود، بی پیامک)، هشدار موبایل‌های تأییدنشده، پرونده قبلی، سابقه وضعیت و ورودی‌ها.
  - «شروع مشاوره» (فقط `new`)، «بستن پرونده» فقط با علت از فهرست، «لغو پیامک‌ها» با دلیل (`lead.update_cases`).
  - **هیچ جزئیات اعتباری** (سند ۰۴: مشاور فقط وضعیت را می‌بیند).
  - نوبت‌های این پرونده (`booking.book_for_patient`؛ فقط مشاور واگذارشده، همان قاعده سرویس).
- **`/leads/[id]/book`، «نوبت برای بیمار»:** جست‌وجوی عمومی پزشک با رشته و شهر پرونده، زمان آزاد در تقویم واحد، نگه‌داشتن با موبایل تأییدشده اول شخص (مسیر `booking/advisor`)، سپس درخواست. بی موبایل تأییدشده یا با شخص مسدود: گرفته نمی‌شود.

## تغییر API (فقط نوع پاسخ)

`@ZodResponse` روی `POST /lead/intakes`، `GET /lead/cases`، `GET /lead/cases/:id`، سه اقدام پرونده، `GET /lead/abandonment-reasons` و سه مسیر `booking/advisor`. شِماها در `packages/contracts/src/lead/lead.ts` (افزودنی). harness هر پاسخ را با شِما می‌سنجد: آزمون‌های lead و نوبت **۹۵ از ۹۵**.

## تصمیم‌ها

1. **کدام پنل:** پنل داخلی (مشاور کارمند سپهر است، پشت VPN، R10). پنل مراکز نه.
2. **موبایل کامل به مشاور نشان داده می‌شود** (برای تماس)، همان که API امروز به دارنده پرونده می‌دهد. موبایل تأییدنشده نشان داده نمی‌شود، فقط شمارش.
3. **نوبت با موبایل تأییدشده اول.** انتخاب بین چند موبایل ساخته نشد.
4. **خدمت نوبت:** همان خدمت قیمت نتیجه جست‌وجو (ویزیت). انتخاب خدمت دیگر ساخته نشد.
5. **صفحه‌های مدیر استراتژی** (درصد تخصیص، حضور، سقف، تخصیص دستی، علت‌ها، مسدودسازی، ادغام، ورود اکسل سرنخ) ساخته نشدند؛ API هست. پیشنهاد تسک بعد.
6. **seed e2e:** مشاور موجود seed صف `advisory` را ۱۰۰٪ می‌گیرد، تا سرنخ تازه به او برسد. فقط پایگاه دورریختنی e2e.

## آزمون‌ها

- آزمون‌های موجود lead و `appointments.int` (۵ فایل، ۹۵) با شِماهای پاسخ سبز.
- e2e `leads.spec.ts`: ثبت سرنخ، پرونده در فهرست مشاور، شروع مشاوره، جست‌وجوی پزشک، نگه‌داشتن زمان، درخواست نوبت، نوبت در پرونده؛ `checkPage` (تاریخ شمسی و a11y) سه بار.
