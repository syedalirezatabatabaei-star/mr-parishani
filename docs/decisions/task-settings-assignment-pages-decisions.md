# صفحه تنظیمات و صفحه تخصیص — تصمیم‌ها (دور هفدهم، ۱۴۰۵/۰۷/۲۴)

دستور مالک، بند ۲: «صفحه تنظیمات پرچم‌های هویت و کلیدهای lead/booking/SMS را بساز، فقط با APIهای موجود، با تغییر دونفره و audit؛ پیش‌فرض همه پرچم‌ها خاموش. صفحه تخصیص لید برای مدیر استراتژی را هم بساز.» غیرمالی. **مهاجرت لازم نشد.**

## صفحه تنظیمات، `/settings`

- **فقط API موجود پیکربندی:** `GET /config/keys/:key/versions`، `POST /config/proposals`، `POST /config/proposals/:id/approve|reject`. هیچ تغییری در API.
- **۲۵ کلید:** هویت (۳ پرچم و ۵ کلید)، سرنخ (۵)، نوبت (۷)، پیامک (۵). فهرست در `apps/admin/lib/settings-keys.ts`.
- **دونفره در سرور:** همه ۲۵ کلید `sensitive` هستند؛ سرویس پیکربندی و قید پایگاه داده پیشنهاددهنده را برای تأیید یا رد رد می‌کنند (`second_person_required`). آزمون واحد `settings-keys.test.ts` می‌گوید هر کلید صفحه حساس است و مجوز صفحه همان مجوز دسته کلید است (`config.manage_technical` یا `config.manage_business`). جهش «مجوز اشتباه» و «کلید غیرحساس» هر دو قرمز.
- **audit:** هر پیشنهاد و تصمیم را سرویس پیکربندی ثبت می‌کند (رفتار موجود).
- **پرچم‌ها:** فرم روشن یا خاموش با انتخاب پیش‌فرض «خاموش»؛ برای `{ enabled }` بقیه مقدار (مثل `windowSeconds`) حفظ می‌شود. کلیدهای دیگر: JSON از مقدار جاری، همان الگوی صفحه طرح‌ها و قواعد.
- **مقدار امروز پرچم‌ها روی پایگاه محلی:** `identity.reauth`، `identity.factor_change_sms`، `identity.staff_mobile_required`، `lead.excel_import_enabled` و `notification.promotional_campaigns_enabled` **خاموش‌اند**. **`lead.returning_to_previous_agent` روشن است**: قاعده سند ۰۵ §۴ (بازگشتی به مشاور قبلی) است، نه پرچم ویژگی؛ دست نخورد. خاموش کردنش اکنون یک پیشنهاد دونفره در همین صفحه است.

## صفحه تخصیص، `/assignment` (مدیر استراتژی)

- سهم‌های جاری یک صف (و اختیاری برای شهر و رشته)، با نام کارشناس؛ نسخه تازه با افزودن کارشناس با نام کاربری، درصدهای صحیح با جمع ۱۰۰ و دلیل؛ حضور و سقف هر کارشناس با دلیل؛ هدف در برابر واقعی سی روز گذشته.
- **API افزوده (فقط خواندنی):**
  - `GET /lead/agents/by-username/:username` (`lead.manage_assignment`): فقط حساب کارمند فعال؛ نه مرکز، نه بیمار، نه غیرفعال؛ بی موبایل. از درگاه `ACCOUNT_DIRECTORY`.
  - `GET /lead/assignment/shares` حالا نام هر کارشناس را هم می‌دهد (`name`). audit فقط شناسه‌ها را نگه می‌دارد.
  - `@ZodResponse` روی مسیرهای سهم، حضور، سقف و گزارش توزیع.
- **دونفره نیست:** تغییر سهم، حضور و سقف همان رفتار موجود API است (یک‌نفره، با audit). دونفره کردن آن تصمیم مالک است.
- **حضور و سقف جاری** نشان داده نمی‌شوند (API خواندنش را ندارد)؛ فقط ثبت تازه.
