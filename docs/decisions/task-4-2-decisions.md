# تسک ۴-۲ — رسید فیزیکی و ابزار تضمین

سند مرجع: `docs/12-contract-funding-service.md` §۳؛ `docs/13-build-plan-phase-4.md` ۴-۲؛ واژه‌نامه (`PhysicalDelivery`، `Instrument`)؛ قاعده ۲۷ (رمزگذاری سطح فیلد و blind index) و ۳۰ (لاگ بی‌داده شخصی).

**مالی است؟** نه. مبلغ چک و سفته فقط ثبت می‌شود؛ ثبت دفتر کل، کیف یا اقساط ندارد. **مسدودکننده؟** نه.

**پذیرش:**
- جست‌وجو با شماره چک از راه blind index کار کند.
- ستون خام رمزگذاری‌شده باشد.
- آزمون عدم ظهور شماره در لاگ.

## مدل (ماژول `instrument`)

### `physical_deliveries`، `physical_delivery_items`

- **ساخت:** کارشناس تکمیل یک تحویل برای پرونده اعتباری تأییدشده (یا شرطی) می‌سازد، با اقلام مورد انتظار: قرارداد امضاشده، چک، سفته، سایر. یعنی `awaiting_send`.
- **چرخه** (trigger؛ قاعده ۸):
  - `awaiting_send` → `sent` | `received`
  - `sent` → `received` | `returned`
  - `received` → `verified` | `incomplete` | `returned`
  - `incomplete` → `verified` | `returned`
  - `verified` → `archived`
  - `archived` → `released`
- **ارسال:** بیمار یا وام‌گیرنده اعلام می‌کند که فرستاده است، با روش (پیک، پست، حضوری) و کد رهگیری.
- **رسیدن:** کارشناس دریافت را ثبت می‌کند: تحویل‌گیرنده و زمان. سپس هر قلم را «رسید» یا «نرسید» می‌زند.
- **بررسی:**
  - همه اقلام رسیده و همه ابزارها بررسی‌شده ← `verified`.
  - وگرنه ← `incomplete`، با فهرست کمبود، و **پیامک به صاحب پرونده** (فقط نام اقلام؛ هرگز شماره).
- **بایگانی:** با محل بایگانی ← `archived`. ابزارهای بررسی‌شده `held` می‌شوند.
- **`released`** (استرداد پس از تسویه با تأیید حسابداری) در فاز ۶ است. trigger آن را می‌پذیرد ولی API ندارد.

### `instruments`

- **ستون‌ها:** طبق سند ۱۲ §۳، به‌علاوه `number_last4`، تنها بخشی از شماره که نشان داده می‌شود.
- **شماره:**
  - **پیش از ذخیره:** ارقام یکسان‌سازی و فاصله و خط تیره حذف می‌شود (قاعده ۲۳).
  - **ذخیره:** رمزگذاری AES-GCM با context `instruments.number`، و blind index با دامنه تازه `instrument_number`.
  - **یکتایی:** هر نوع ابزار و هر شماره فقط یک ردیف.
- **چرخه:**
  - `received` → `verified` → `held` → `released` | `presented`
  - `presented` → `cleared` | `bounced`
  - `bounced` → `legal_action`
  - فاز ۴ فقط تا `held` را API می‌دهد. وصول و برگشت در فاز ۶ است.
- **صیاد:** کارشناس فقط تأیید می‌کند که صادرکننده چک را در سامانه صیاد ثبت کرده است، و تاریخ آن ثبت می‌شود. اتصال برخطی نیست. چک بدون این تأیید `verified` نمی‌شود.
- **دیدن شماره کامل:** endpoint جدا، فقط با مجوز، که هر مشاهده را ثبت می‌کند (سند ۰۴ §۷). فهرست‌ها و نماها فقط چهار رقم آخر را دارند.
- **جست‌وجو:** `GET /instruments?number=` از راه blind index، بی‌رمزگشایی.
