# تسک ۹-۲: اسکن خودکار

> **وضعیت:** انجام شد (حالت خودکار). ۱۴۰۵/۰۷/۱۸.
>
> - **گزارش:** `docs/security/scan-report-9-2.md`.
> - **پذیرش:** هیچ بحرانی یا بالایی بی تسک رفع نماند (R14 تا R17).

## تصمیم‌ها

- **تصویرهای ZAP و trivy:** با اجازه مالک دریافت و با digest ثبت شدند (۱۴۰۵/۰۷/۱۸).
- **پایگاه داده trivy:**
  - **مانع:** از `mirror.gcr.io` با ۴۰۳ مسدود است.
  - **منبع جایگزین:** از ghcr (`--db-repository`).
- **«staging محلی» همان stack e2e است**، با داده ساختگی.
- **ZAP:** اسکن فعال API از روی OpenAPI، برای ناشناس و هر نقش با توکن bearer همان نقش.
  - **سقف هر اسکن:** ۸ دقیقه، چون توکن دسترسی ۱۰ دقیقه است.
- **اسکریپت تازه:** `apps/e2e/src/security-scan.ts` (`pnpm --filter @sepehr/e2e security:zap`). امکانات:
  - ادامه از نقش (`ZAP_ONLY`).
  - بررسی زنده بودن API پیش از هر اسکن.
  - ذخیره خروجی stack.
- **stack e2e:** خروج هر سرویس را با کد و signal گزارش می‌کند.

## یافته‌ها و اصلاح‌های همین تسک

1. **gitleaks:** دو مثبت کاذب (کلید ثابت ظرف آزمون SeaweedFS).
   - کلیدهای آزمون در هر اجرا تصادفی شدند.
   - commitهای قدیمی فقط با fingerprint در `.gitleaksignore` آمدند.
   - **نتیجه:** «no leaks found».
2. **ZAP، «API down» نادرست:** اتصال keep-alive کهنه در خود اسکن‌کننده بود.
   - **نشانه:** `ECONNABORTED` روی سوکتی که API پس از ۵ ثانیه بی‌کاری بسته بود.
   - **تأیید:** API در هیچ اسکن از کار نیفتاد. خروجی stack هیچ خروج سرویسی نشان نداد.
   - **اصلاح:** تلاش دوباره روی اتصال تازه.
3. **یافته فرایندی:** اسکریپت‌های امنیتی CI از تسک ۰-۵ اجرا نشده بودند (بی push). اقدام R17.
