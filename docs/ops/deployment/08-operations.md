# ۸. پایش، به‌روزرسانی، برگشت، حادثه و کارهای دوره‌ای

[فهرست راهنما](../deployment-guide.md)

## ۸.۱ پایش

همه **خودمیزبان** (قاعده ۱۷ تا ۱۹). اجزا و هشدارها: `ops/monitoring/README.md`. پیکربندی‌ها: `ops/monitoring/prometheus.yml`، `ops/monitoring/alertmanager.yml`، `ops/alerts/queues.yml`، `ops/alerts/platform.yml`.

**جای اجرا: پس از تعیین مشخصات سرور** (همان سرور یا سرور جدا). پیشنهاد: سرور جدا یا دست‌کم دیسک جدا، تا پر شدن دیسک لاگ پایگاه را نخواباند.

| هشدار حیاتی | قاعده | کانال |
|---|---|---|
| مغایرت تطبیق دفتر کل، تسویه، پیش‌پرداخت | `ReconciliationMismatch` | پیامک worker به `ALERT_SMS_MOBILES` |
| رشد صف | `OutboxBacklog`، `QueueBacklog`، `QueueFailedJobs` | پیامک worker |
| خطای پیامک | `SmsJobsFailing`، `SmsBacklog` | Prometheus؛ **کانال دوم لازم** (اگر پیامک خراب است، پیامک کانال نیست؛ سؤال ۱۲ فصل ۱۰) |
| پر شدن دیسک | `DiskFilling`، `DiskAlmostFull` | Prometheus |
| تأخیر replica | `ReplicaLag`، `ReplicaLagSevere` | Prometheus |
| پشتیبان | `WalArchiveStale`، `BaseBackupStale`، `SecondCopyStale`، `BackupMetricsMissing` | Prometheus |
| گواهی | `CertificateExpiresSoon`، `CertificateExpiresVerySoon` | Prometheus |

**هشدارهای تازه برای سرور داخلی** (هنوز قاعده ندارند؛ `phase-10-readiness.md` §۶.۲): باتری UPS، پر شدن دیسک پشتیبان، شکست کپی بیرونی، قطع اینترنت (از بیرون دیده می‌شود؛ سؤال ۱۲).

**پیش از اتکا:** `promtool check rules` و `amtool check-config` از ایمیج mirror داخلی؛ روی این ماشین اجرا نشده‌اند. یک هشدار آزمایشی از هر گروه روی staging آتش شود و پیامکش برسد.

## ۸.۲ به‌روزرسانی (انتشار)

دستورالعمل کامل: `docs/runbooks/release.md`. روی سرور داخلی:

1. **پیش از انتشار:** همه در `main` با CI سبز؛ تأیید بازبین کد مالی (۱۰-۰)؛ `CHANGELOG.md` و برچسب نسخه.
2. **staging اول**، همان commit یا همان digest ایمیج.
3. **production:**
   - ساعت کم‌بار؛ **نه** ۰۰:۰۰ تا ۰۳:۳۰ تهران؛ **نه** روز ۱۰ هر ماه (پرداخت تسویه).
   - پشتیبان منطقی تازه و ثبت شمار مهاجرت.
   - `git fetch` و `git checkout <برچسب>`، `pnpm install --frozen-lockfile`، `pnpm build`.
   - اگر مهاجرت تازه هست: آیین کامل ([فصل ۳](03-database.md#۳۵-آیین-مهاجرت))، سپس `pnpm db:migrate`.
   - راه‌اندازی دوباره: worker متوقف، api، وب و پنل دوباره، worker آخر.
   - `pnpm ops:launch-check`؛ Grafana ۳۰ دقیقه؛ تطبیق همان شب پاک.
4. **سیستم‌عامل، Postgres، Redis و Node:** جدا از انتشار برنامه، هر کدام با پشتیبان پیش از آن و روی staging اول.

## ۸.۳ برگشت

- **برنامه:** `git checkout <برچسب قبلی>`، ساخت، راه‌اندازی دوباره (یا digest ایمیج قبلی). **مهاجرت‌ها برنمی‌گردند**؛ چون expand/contract‌اند، نسخه قبل با طرح تازه کار می‌کند.
- **قابلیت:** خاموش کردن پرچمش (دونفره در پنل)، بی برگشت کد.
- **مهاجرتی که داده را خراب کرده:** `docs/runbooks/backup-restore.md`، با زمان هدف پیش از مهاجرت.
- **هدف برگشت:** کمتر از ۱۵ دقیقه، تمرین‌شده (`task-10-1-plan.md` §۸).

## ۸.۴ حادثه

دستورالعمل: `docs/runbooks/incident.md`. خلاصه:

| شدت | نمونه | پاسخ |
|---|---|---|
| ۱ | سامانه بالا نیست؛ مغایرت دفتر کل؛ گمان نشت؛ پشتیبان کار نمی‌کند | فوری، شبانه‌روز؛ مالک و مسئول فنی |
| ۲ | ورود، نوبت، شارژ یا تسویه خراب؛ پیامک نمی‌رود؛ صف‌ها رشد می‌کنند | ساعت کاری فوری؛ شب اگر بیش از ۱ ساعت |
| ۳ | یک صفحه یا گزارش؛ کندی | روز کاری بعد |

گام‌ها: ثبت ← ارزیابی ۱۵ دقیقه (Grafana، Loki، `pnpm ops:launch-check`، آخرین تطبیق) ← مهار ← رفع ← بستن ← گزارش بی‌سرزنش ظرف ۵ روز کاری.

**مهار، هرگز با اصلاح دستی داده.** مسیر مالی مشکوک: پرچمش خاموش. گمان نفوذ: نشست‌ها بسته (`docs/runbooks/staff-offboarding.md`)، در صورت لزوم پنل داخلی کاملاً بسته (`INTERNAL_PANEL_CIDRS` خالی و راه‌اندازی دوباره api)، سپس `docs/runbooks/key-rotation.md`.

دستورالعمل‌های دیگر: `docs/runbooks/kavenegar-outage.md`، `national-internet.md`، `ledger-mismatch.md`.

## ۸.۵ کارهای دوره‌ای

| تناوب | کار | مسئول |
|---|---|---|
| هر روز صبح | هشدارهای شب؛ تطبیق ۰۲:۰۰ تا ۰۲:۲۰ پاک بود؛ پشتیبان پایه ۰۱:۳۰ موفق؛ صف‌ها؛ دیسک | نوبت‌کار عملیات |
| هر روز | پایش روزانه پایلوت (`go-no-go.md` §۲) | نوبت‌کار |
| هر هفته | به‌روزرسانی امنیتی سیستم‌عامل؛ حساب‌های SSH و VPN با فهرست کارکنان؛ حساب‌های بی‌استفاده پنل؛ گزارش هفتگی پایلوت (`go-no-go.md` §۳) | مسئول سرور، مدیر سیستم |
| هر ماه | `pnpm ops:launch-check`؛ فضای دیسک پشتیبان؛ کپی بیرونی واقعاً رسیده؛ بررسی امضاهای ClamAV تازه | مسئول سرور |
| هر سه ماه | **تمرین بازیابی** ([فصل ۷](07-backup-restore.md#۷۶-تمرین-بازیابی-شرط-go-live))؛ تمرین برگشت انتشار | مسئول سرور و مالک |
| هر سال | چرخش رازها ([فصل ۴](04-secrets.md#۴۴-چرخش))؛ بازبینی سهم‌های کلید (دو از سه)؛ تمدید گواهی (از ۶۰ روز پیش؛ هشدار ۳۰، ۱۴ و ۷ روز به دو مسئول)؛ تعطیلات سال بعد پیش از ۱ بهمن (مدیرعامل، تأیید با قائم‌مقام فقط تعطیلات) | مسئول سرور، مالک، مدیرعامل |
| با خروج هر کارمند | خروج دونفره در پنل؛ همان روز VPN و SSH | مدیر سیستم، مسئول سرور |
