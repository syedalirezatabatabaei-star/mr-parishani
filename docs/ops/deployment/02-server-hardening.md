# ۲. سخت‌سازی سرور

[فهرست راهنما](../deployment-guide.md)

> **همه فرمان‌های این فصل آزمایش‌نشده‌اند** و برای خانواده Debian یا Ubuntu LTS نوشته شده‌اند. سیستم‌عامل **پس از تعیین مشخصات سرور** قطعی می‌شود. هر فرمان پیش از اجرا روی staging سنجیده شود.

## ۲.۱ کاربرها

1. برای هر مدیر سرور یک حساب شخصی بسازید. **هیچ حساب مشترک**:
   ```sh
   sudo adduser <نام-مدیر>
   sudo usermod -aG sudo <نام-مدیر>
   ```
2. حساب سرویس برنامه، بی ورود و بی `sudo`:
   ```sh
   sudo adduser --system --group --home /opt/sepehr --shell /usr/sbin/nologin sepehr
   ```
3. حساب `root` قفل بماند. ورود فقط با حساب شخصی و `sudo`.
4. فهرست کسانی که SSH دارند در دفتر عملیات ثبت شود. با خروج هر نفر، حسابش همان روز بسته شود ([فصل ۸](08-operations.md#۸۵-کارهای-دوره‌ای)؛ `docs/runbooks/staff-offboarding.md`).

## ۲.۲ کلید SSH

1. هر مدیر روی **رایانه خودش** کلید می‌سازد (`ssh-keygen -t ed25519`). کلید خصوصی هرگز از رایانه‌اش بیرون نمی‌آید و برای کسی فرستاده نمی‌شود.
2. فقط کلید عمومی (فایل `.pub`) به سرور می‌رود: `~<نام-مدیر>/.ssh/authorized_keys`.
3. در `/etc/ssh/sshd_config` (نمونه کامل در [فصل ۱۰](10-appendix.md#۱۰۲-نمونه-پیکربندی)):
   - `PermitRootLogin no`
   - `PasswordAuthentication no`
   - `KbdInteractiveAuthentication no`
   - `AllowUsers <نام-مدیر-۱> <نام-مدیر-۲>`
4. **پیش از بستن نشست فعلی**، در پنجره دوم ورود با کلید را بیازمایید. اگر نشد، با نشست اول برگردید و درست کنید. بستن نشست اول پیش از آزمون یعنی قفل شدن بیرون از سرور.
5. `sudo systemctl reload ssh`.
6. **تصمیم مالک ۱۴۰۵/۰۸/۰۲:** SSH **فقط از VPN**، فقط با کلید، و فقط برای نفرات نام‌برده (دیواره آتش، پایین). بازه VPN: **پس از تعیین مشخصات سرور**.

## ۲.۳ به‌روزرسانی

1. پیش از نصب هر چیز: `sudo apt update && sudo apt upgrade`.
2. به‌روزرسانی امنیتی خودکار: بسته `unattended-upgrades`، فقط مخزن امنیتی.
3. **در دوره اینترنت ملی** مخزن‌های خارجی در دسترس نیستند. منبع بسته‌ها باید mirror داخلی باشد (**پس از تعیین مشخصات سرور**؛ سؤال ۶ فصل ۱۰).
4. **Postgres، Redis و Node با به‌روزرسانی خودکار عوض نشوند.** نسخه آن‌ها فقط با انتشار برنامه‌ریزی‌شده (`docs/runbooks/release.md`). برای بسته‌های Postgres: `sudo apt-mark hold` روی بسته‌های اصلی.
5. راه‌اندازی دوباره پس از به‌روزرسانی هسته: فقط در ساعت کم‌بار، **نه** در پنجره ۰۰:۰۰ تا ۰۳:۳۰ تهران که کارهای شبانه مالی اجرا می‌شوند ([فصل ۵](05-application.md#۵۸-کارهای-زمان‌بندی‌شده)).

## ۲.۴ دیواره آتش

قاعده: **هر چیزی بسته، مگر صریحاً باز.**

| ورودی | از کجا | چرا |
|---|---|---|
| ۴۴۳/tcp | همه | وب بیمار، پنل مراکز، پنل داخلی (پنل داخلی در خود برنامه هم به VPN بسته است) |
| ۸۰/tcp | همه | فقط انتقال به ۴۴۳ |
| ۲۲/tcp | فقط بازه VPN (تصمیم مالک ۱۴۰۵/۰۸/۰۲) | SSH |
| هر پورت دیگر | هیچ‌جا | پایگاه ۵۴۳۲، Redis ۶۳۷۹، S3 ۸۳۳۳، ClamAV ۳۳۱۰، api ۳۰۰۰، وب ۳۰۰۱، پنل ۳۰۰۲، پایش: فقط روی `127.0.0.1` یا شبکه خصوصی |

| خروجی | به کجا |
|---|---|
| کاوه‌نگار (HTTPS) | پیامک |
| NTP داخلی | ساعت |
| mirrorهای داخلی | بسته‌ها، ایمیج‌ها، npm، امضاهای ClamAV |
| مقصد کپی بیرونی پشتیبان | [فصل ۷](07-backup-restore.md) |
| همه چیز دیگر | بسته |

نمونه با `ufw` (**آزمایش‌نشده**؛ بازه VPN **پس از تعیین مشخصات سرور**):

```sh
sudo ufw default deny incoming
sudo ufw default deny outgoing
sudo ufw allow in 443/tcp
sudo ufw allow in 80/tcp
sudo ufw allow in from <بازه-VPN> to any port 22 proto tcp
sudo ufw allow out to <آی‌پی-NTP-داخلی> port 123 proto udp
sudo ufw allow out to <آی‌پی-mirror> port 443 proto tcp
sudo ufw allow out to <آی‌پی‌های-کاوه‌نگار> port 443 proto tcp
sudo ufw allow out 53
sudo ufw enable
```

**هشدار:** اگر برنامه‌ها در Docker اجرا شوند، Docker قاعده‌های خودش را می‌نویسد و ممکن است `ufw` را دور بزند. پس پورت هر کانتینر فقط روی `127.0.0.1` منتشر شود (مثل `docker-compose.yml` مخزن: `127.0.0.1:5432:5432`)، و پس از نصب با `ss -tlnp` بسنجید که هیچ سرویسی جز پراکسی روی `0.0.0.0` گوش نمی‌دهد.

## ۲.۵ fail2ban

1. نصب: `sudo apt install fail2ban`.
2. فایل `/etc/fail2ban/jail.local` (نمونه در [فصل ۱۰](10-appendix.md#۱۰۲-نمونه-پیکربندی)):
   - `sshd` روشن.
   - زندان برای پراکسی معکوس (پاسخ‌های ۴۰۱ و ۴۲۹ پیاپی) **اختیاری** است. خود برنامه محدودیت نرخ و قفل حساب دارد (`identity.otp`: ۸ ارسال در ساعت و قفل ۹۰۰ ثانیه پس از ۶ خطا؛ `identity.lockout`). زندان IP روی پراکسی ممکن است کاربران پشت یک IP مشترک (یک مرکز درمانی) را با هم ببندد. پیشنهاد: فقط `sshd`.
3. **آدرس VPN و دفتر را در `ignoreip` بگذارید**، تا یک مدیر با چند ورود اشتباه خودش را بیرون نیندازد.

## ۲.۶ موارد دیگر

- **ساعت:** `chrony` یا `systemd-timesyncd` با منبع NTP داخلی؛ `timedatectl` باید «synchronized: yes» نشان دهد. روی سرور پایگاه هم.
- **ثبت ورودها:** `auth.log` نگه داشته و به Loki فرستاده شود (بی داده شخصی بیماران؛ قاعده ۳۰).
- **دیسک:** پوشه داده Postgres و پوشه پشتیبان روی دو دیسک جدا. هشدار پر شدن (`DiskFilling`، `DiskAlmostFull`).
- **سرویس‌های بی‌کار** خاموش شوند (`systemctl list-unit-files --state=enabled`).
- **رمزگذاری دیسک:** پیشنهاد می‌شود، ولی کلید باز کردنش پس از برق‌رفتگی باید در دسترس باشد، وگرنه RTO ۴ ساعت شکسته می‌شود. تصمیم با مالک (سؤال ۷ فصل ۱۰).
